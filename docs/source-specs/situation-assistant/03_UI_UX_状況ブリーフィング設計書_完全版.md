# UI/UX 設計書 — 状況ブリーフィング（完全版）

Last updated: 2026-05-26

> **概念修正の補助 SoT**: `docs/project/concept-layer-correction.md`（Issue #31）
> 本書が扱うブリーフィングタブは、状況補佐官の全体ではなく、**4D テキスト出力チャネル**の表示先である。

---

## 1. 設計原則

1. **ノーサプライズ**: 既存 BottomMonitor の操作パターンを踏襲する。新しい UI パターンを導入しない。
2. **mock ファースト**: 実 AI 未接続でも動作する。mock バナーで状態を明示する。
3. **情報密度の制御**: 4D ブリーフィングは折りたたみ可能。デフォルトは展開表示。
4. **操作最小化**: ボタン 1 つで生成。設定は最小限。
5. **チャネル中立**: ブリーフィングタブは**1 つの出力チャネル**の表示先であり、状況補佐官全体ではない。将来、音声 / アバター / 動画 / 動的ハイライトといった別チャネルが追加される前提で設計する。

---

## 2. このタブの位置づけ

このタブは、状況説明生成レイヤーの**最小出力チャネル**である 4D テキストブリーフィングの表示先である。

- 状況補佐官の全体ではない。
- TTS / アバター / 動画 / 動的ハイライトは別チャネルとして将来追加される。
- 認知HUD本体ではない（認知HUDは Canvas / Inspector / 通知 / モーダル等に分散する注意配分レイヤー）。

---

## 4. UI コンポーネント仕様

### 4.1 生成コントロール

| 要素 | 仕様 |
|---|---|
| 生成ボタン | `primary-button`、テキスト: 「ブリーフィングを生成」 |
| 生成中 | スピナー + 「生成中...」+ キャンセルボタン |
| 入力ソース選択 | `<select>`: 全ログ / 最新 Run のみ / エラーのみ |

### 4.2 ブリーフィング表示カード

| 要素 | 仕様 |
|---|---|
| ヘッダー | 「📋 ブリーフィング」+ 重要度バッジ + 生成日時 |
| 本文 | 4D セクション（What / Why / How / Next）、テキストノードとしてレンダリング |
| 折りたたみ | セクション単位で折りたたみ可能（将来機能）。MVP は全展開固定 |
| mock バナー | 実 API 未接続時: 警告バナー |
| チャネル切替（将来） | テキスト / 音声 / アバター / 動画 / 動的ハイライト の選択 |

### 4.3 重要度バッジ

| 値 | 表示色 | CSS クラス例 |
|---|---|---|
| `info` | グレー / 青 | `.badge-info` |
| `warn` | オレンジ | `.badge-warn` |
| `error` | 赤 | `.badge-error` |

## 5. インタラクション仕様

### 5.1 生成ボタン押下

```
[生成ボタン] →
  status = 'generating'
  ボタン disabled + スピナー表示
  →（完了）status = 'done', ブリーフィング表示
  →（失敗）status = 'error', エラーバナー表示
```

### 5.2 再生成

- 生成完了後もボタンは有効。再押下で最新状態から再生成する。
- 前回のブリーフィングは新しいものに上書きされる。

### 5.3 空状態（初期表示）

```
ブリーフィングはまだ生成されていません。
「ブリーフィングを生成」を押してください。

ヒント: Run を実行した後に生成すると、実行状態の説明が得られます。
```

---

## 6. アクセシビリティ

- 生成ボタン: `aria-label="状況ブリーフィングを生成"`
- スピナー: `aria-label="生成中"` + `role="status"`
- 重要度バッジ: `aria-label="重要度: {severity}"`
- エラーバナー: `role="alert"`

---

## 7. 認知HUD との関係

本書で扱うブリーフィングタブは、認知HUD本体ではない。

- **認知HUD**: 注意配分編集レイヤー。Canvas / Inspector / 通知 / モーダル等に分散する。HUD バッジ / フォーカス / 減光 / Critical 短音通知などを担う。
- **状況ブリーフィングタブ**: 状況説明生成レイヤーの 4D テキスト出力チャネルの表示先。

ブリーフィングタブの内容は、認知HUD が選別・圧縮・強調した情報を**自然言語で時間軸つきに説明**したものである。HUD Signal そのものの表示形態は変更しない。

---

## 8. モバイル / レスポンシブ

MVP では BottomMonitor の既存レスポンシブ挙動を踏襲する。専用対応は不要。

## 9. 将来拡張（MVP スコープ外、概念削除禁止）

| 出力チャネル / 機能 | 優先度 | 補足 |
|---|---|---|
| セクション折りたたみ | 低 | MVP では全展開で十分 |
| 音声読み上げ（TTS / Voice Generator） | 中 | Audio Alert Briefing と統合 |
| アバター説明（Avatar Narrator） | 中 | シミュレーションゲーム解説役・進行支援アバターへの応用 |
| 動的ハイライト（Visual Explanation Render） | 中 | Canvas のノード / エッジ / メーターを動的に強調 |
| 動画化（Workflow News Video / Briefing Video Composer） | 中 | 失敗・承認待ち・コスト急増などに限定して生成 |
| Timeline Narration | 中 | 過去 → 現在 → 未来の時系列ナレーション |
| Incident Replay | 中 | 失敗・詰まり・承認待ちの再生 |
| Next Action Briefing 単独表示 | 中 | 「次に何をすべきか」だけを大きく表示するモード |
| ブリーフィング履歴保存 | 中 | durable run history と連動 |
| カスタムプロンプト入力 | 中 | 上級ユーザー向け |

これらは MVP スコープ外だが、**当初発想の重要な応用先**として削除・縮小しない。
