## 3. データフロー

### 3.1 MVP

```
AppShell
  runLogs: RunLog[]
  metrics: WorkflowMetrics
  executionGraph: ExecutionGraph | null
  connectorJobs: ConnectorJob[]
  runTrace: RunTrace | null
  hudSnapshot: HudSnapshot
      ↓ props
BottomMonitor
      ↓ props
BriefingPanel
      ↓ 使用
useBriefingGenerator(inputs, adapter)
      ↓
BriefingInputCollector.collect(inputs)
      → BriefingInput (フィルタリング済み)
      ↓
BriefingPromptBuilder.build(briefingInput)
      → prompt: string
      ↓
adapter.generate({ prompt, input })
      → BriefingResult
      ↓
状態更新 → UI 再描画
```

### 3.2 本来仕様（マルチチャネル）

入力は同じ `BriefingInput` を共有し、後段で複数チャネルへ分岐する。Script Writer の出力（解説台本）が Voice / Avatar / Video / Highlight Renderer に共有される構造とする。

## 4. 型定義

```typescript
// src/domain/briefing.ts

export type BriefingSeverity = 'info' | 'warn' | 'error'

export type BriefingResult = {
  what: string
  why: string
  how: string
  next: string
  severity: BriefingSeverity
  isMock: boolean
  generatedAt: string  // ISO date string
}

export type BriefingStatus = 'idle' | 'generating' | 'done' | 'error'

export type BriefingState = {
  status: BriefingStatus
  result: BriefingResult | null
  error: string | null
}

export type BriefingInputMode = 'all' | 'latest-run' | 'errors-only'

export type BriefingInput = {
  workflowName: string
  executionMode: string
  overallStatus: string
  logEntries: string[]      // Credential フィルタリング済み
  errorEntries: string[]
  metrics: Record<string, unknown>
  retryCandidates: string[]
  runDetail?: RunDetailSummary  // ステップ証跡（サニタイズ済み）
  hudSummary?: HudSnapshotSummary
}
```

将来、マルチチャネル化に伴い `BriefingScript`（解説台本）を導入し、Voice / Avatar / Video Adapter が同一 script から派生出力を生成する設計とする。

## 6. 安全境界

### 6.1 Credential 除外ルール

`BriefingInputCollector` は以下を除外する:

- `node.config` の全フィールド（自由記述を含む）
- `connector.credential` の全フィールド
- ログ内の `password`, `token`, `key`, `secret`, `apiKey`, `credential`, `authorization`, `bearer` を含むエントリ（大文字小文字不問）
- raw provider payload / artifact content / prompt 本文

### 6.2 送信先制御

- MVP（MockBriefingAdapter）: ネットワーク通信なし
- ClaudeBriefingAdapter: Anthropic API のみ。ユーザー設定で有効化が必要
- 将来のマルチチャネル Adapter: 各チャネルが独自の送信先制御を持つ。動画 / 音声 / アバター生成 API はそれぞれ Credential 管理方針確定後に許可

### 6.3 ログサイズ制限

- 入力テキスト上限: 8,000 トークン相当（約 32,000 文字）
- 超過時: 最新エントリを優先し古いものを切り詰める

### 6.4 動画化・音声化のトリガ制限

「すべてを動画化する」ことは行わない。動画 / 音声 / アバター出力は、原則として失敗 / 承認待ち / コスト急増 / 詰まり / 複数AI判断割れ / 重要成功 / 長時間放置後の再開 などに限定する。詳細は機能仕様書 §7 を参照。

## 7. BottomMonitor 統合方針

`BottomMonitor.tsx` へのタブ追加は以下のパターンで行う:

```typescript
// 既存タブ配列に追加
type MonitorTab = 'HUD' | 'RunDetail' | 'Logs' | ... | 'Storage' | 'Roadmap' | 'Briefing'

// 既存 tabLabels に追加
Briefing: 'ブリーフィング',
```

既存タブの順序・ラベル・動作は変更しない。`認知HUD` タブと `ブリーフィング` タブは別の役割（注意配分サマリ vs 状況説明テキスト）であり、統合しない。

---

## 8. AppShell 統合方針

- `AppShell.tsx` は `runLogs`, `metrics`, `executionGraph`, `connectorJobs`, `runTrace`, `hudSnapshot` を BottomMonitor に渡す。
- 不足する props を追加する際は型定義に `Briefing` 関連フィールドを追加するだけでよく、既存フィールドを変更しない。
