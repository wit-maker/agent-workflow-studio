# AI エージェント運用設計書 — 状況補佐官（完全版）

Last updated: 2026-05-26

> **概念修正の補助 SoT**: `docs/project/concept-layer-correction.md`（Issue #31）
> 状況補佐官は「計画作成 AI」「上位管理者」「指示役」ではない。状況説明生成レイヤーを人間向けの役割として表現したものである。

---

## 1. 役割境界

### 1.1 状況補佐官が担うこと

- 認知HUD で選別・圧縮された情報、Run Trace、ログ、メトリクス、成果物、承認待ち、失敗、詰まり、差分、過去履歴を**読む**。
- それらを材料に、**過去・現在・未来の時間軸**で人間向けの状況説明を生成する。
- 4D ブリーフィング / Timeline Narration / Incident Replay / Avatar Briefing / Audio Alert Briefing / Visual Highlight / Workflow News Video / Next Action Briefing などの出力チャネルへ変換する。
- 次に誰が何を判断すべきかを提示する（Human Decision Prompt）。

### 1.2 状況補佐官が担わないこと

- ワークフローの**計画作成**（プランナー AI の領域）
- ワークフローの**自動実行 / 自動修正**（実行エンジンの領域）
- 注意配分そのものの設計（**認知HUD** レイヤーの領域）
- 単なる TTS / アバター / 動画生成機能の提供（これらは状況補佐官の出力チャネルであり、補佐官の本質ではない）

状況補佐官は読む側 / 説明する側であり、**書く側 / 計画する側ではない**。

## 2. AI モデルゲート

### 2.1 状況補佐官の実装に推奨するモデル

| 作業種別 | 推奨モデル |
|---|---|
| docs 追加・仕様整理 | Claude Sonnet 系 / GPT-5.5 high |
| text briefing MVP 実装 | Claude Sonnet 系 / GPT-5.5 high |
| 設計判断・アーキテクチャ変更 | Claude Opus 系 / GPT-5.5 xhigh |
| マルチチャネル設計（音声 / アバター / 動画） | Claude Opus 系 / GPT-5.5 xhigh |

### 2.2 モデル確認ゲート

状況補佐官の実装を開始する前に以下を確認すること:

1. 現在モデルが上記推奨に一致しているか確認する。
2. 不一致の場合は作業開始前にユーザーへ報告し、継続可否を確認する。
3. 継続指示があった場合はその事実を `PROJECT_STATE.md` に記録して続行する。

## 3. AI エージェントの役割分担

### 3.1 状況補佐官仕様の実装エージェント

| 役割 | 担当 AI |
|---|---|
| 仕様作成・docs 追加 | Claude / Codex |
| BriefingPanel UI 実装 | Claude / Codex |
| MockBriefingAdapter 実装 | Claude / Codex |
| ClaudeBriefingAdapter 実装 | Claude（Anthropic SDK を使用するため） |
| Voice / Avatar / Video Adapter 実装（将来） | 各種 Adapter ごとに専門 AI を割り当てる |
| QA・テスト | Claude / Codex |

### 3.2 エージェント間の引き継ぎルール

- 引き継ぎ時は `PROJECT_STATE.md` の最新状態と `docs/project/concept-layer-correction.md` を参照する。
- 実装中断時は途中状態を `PROJECT_STATE.md` に記録する。
- 次のエージェントへの申し送り事項は `## 次の推奨作業` セクションに記載する。
- 概念定義（認知HUD / 状況説明生成 / 状況補佐官）に変更が必要だと判断した場合は、勝手に書き換えず、`docs/project/concept-layer-correction.md` の改訂提案として記録する。

## 4. 入力材料の参照ポリシー

状況補佐官は以下の材料を読み取り専用で参照する。書き込み・改変は行わない。

| 材料 | 用途 |
|---|---|
| HUD Snapshot / HUD Signal | 認知HUD が選別・圧縮した「今見るべきもの」 |
| Run Trace / Step Evidence | 各ステップの証跡（サニタイズ済み） |
| Run Log | 時系列のイベント列 |
| Metrics | 流量 / 詰まり / コスト / 失敗率 |
| Execution Graph | 経路の現状 |
| Connector Jobs | 外部接続キューの状態 |
| Workflow Structure | 構造の文脈 |
| Run History（将来） | 過去の失敗パターン参照 |
| 成果物 / 差分（将来） | 出力の質的評価 |

これらを横断して、「過去に何が起きたか」「現在どこで止まっているか」「未来に何が起きそうか」「次に誰が何を判断すべきか」を組み立てる。

## 5. プロンプト設計方針

### 5.1 システムプロンプト要件

ブリーフィング生成に使用するシステムプロンプトは以下の制約を満たすこと:

- **役割**: 「あなたは AI ワークフローの状況補佐官（状況説明生成レイヤーを担う役割）」として定義する。計画 AI ではないことを明示する。
- **時間軸**: 過去・現在・未来を扱うことを明示する。
- **言語**: 日本語で出力する（UI 言語方針に準拠）。
- **フォーマット**: What / Why / How / Next の 4 セクションを明示的に要求する。
- **安全制約**: Credential・個人情報に言及しないよう指示する。
- **長さ制約**: 各セクション 100 字以内を指示する。

### 5.2 禁止事項（プロンプト内）

- ユーザーの個人情報・組織情報を含めない
- `node.config` の自由記述フィールドを含めない
- API キー・トークン・パスワードを含めない
- 外部 URL・エンドポイント情報を含めない
- ワークフロー自体の改変指示を生成しない（計画 AI の領域）

### 5.3 プロンプトのバージョン管理

- プロンプトテンプレートは `src/adapters/briefing/` 内に文字列定数として管理する
- プロンプトの変更は PR レビューを経ること
- プロンプトエンジニアリングの試行錯誤はブランチで行い、main へのマージ前に QA を実施する

## 6. 出力安全境界

### 6.1 出力検証

`BriefingAdapter.generate()` の戻り値は以下を検証する:

| チェック | 方法 |
|---|---|
| 型安全性 | `BriefingResult` 型に適合しているか確認 |
| 長さ制限 | 各セクションが 500 字を超えていないか確認 |
| 必須フィールド | `what`, `why`, `how`, `next` がすべて存在するか確認 |
| エスケープ | React JSX テキストノードで表示する |
| 役割逸脱の検出 | 出力に「ワークフローを書き換えました」「自動実行しました」など書く側の宣言が含まれていないか確認 |

### 6.2 失敗時の挙動

- 型チェック失敗: エラーバナーを表示し、詳細ログはブラウザコンソールに出力する
- API タイムアウト（5 秒超過）: `タイムアウトしました` メッセージを表示し、mock モードへフォールバックするかどうかをユーザーに選択させる
- ネットワークエラー: `接続エラー: {message}` を表示する

### 6.3 マルチチャネル出力の安全境界（将来）

- Voice / Avatar / Video の各チャネルは、テキスト出力と同じ安全境界（Credential 除外、role 逸脱検出）を共有する。
- 動画 / 音声 / アバターは、原則として失敗・承認待ち・コスト急増・複数 AI 判断割れなどに限定して生成する（機能仕様書 §7 参照）。

## 7. mock モード運用

### 7.1 mock モードの明示

- mock ブリーフィングは必ず `isMock: true` フラグを保持する
- UI では「⚠ mock モード（実 AI API 未接続）」バナーを常時表示する
- mock バナーを非表示にする設定は提供しない

### 7.2 mock ブリーフィングの品質

- mock であっても、実際の入力データ（ログ数・エラー数・再試行候補数・ステップ証跡件数）を反映した動的テキストを生成する
- 「テストデータです」のような無意味なプレースホルダーは使用しない

---

## 8. 実 AI API 接続への移行条件

以下がすべて満たされた場合のみ ClaudeBriefingAdapter を有効にする:

1. Credential 管理方針が確定している（`docs/architecture/credential-safety-boundary.md` 参照）
2. ユーザーが明示的に API キーを設定している
3. API キーが localStorage / ログ / バンドルに保存されない実装になっている
4. プロンプトの QA が完了している（役割境界 / 時間軸言及を含む）
5. PR レビューが完了している

## 9. Git 権限ルール

状況補佐官の実装に関するコミット権限:

| 操作 | 条件 |
|---|---|
| docs 追加 | 自動許可 |
| Mock 実装の追加 | typecheck / build / lint パス後 |
| BottomMonitor タブ追加 | Browser QA パス後 |
| AppShell 変更 | Browser QA パス後 |
| 実 AI API 接続実装 | ユーザー承認 + 上記移行条件を満たした後 |
| マルチチャネル Adapter 追加 | 各チャネルごとの Credential / 送信先制御確定後 |
| 概念定義の変更 | `docs/project/concept-layer-correction.md` の改訂レビュー後 |
| main へのマージ | PR レビュー完了後 |
