2. 不一致の場合は作業開始前にユーザーへ報告し、継続可否を確認する。
3. 継続指示があった場合はその事実を `PROJECT_STATE.md` に記録して続行する。

## 3. プロンプト設計方針

### 3.1 システムプロンプト要件

ブリーフィング生成に使用するシステムプロンプトは以下の制約を満たすこと:

- **言語**: 日本語で出力する（UI 言語方針に準拠）
- **フォーマット**: What / Why / How / Next の 4 セクションを明示的に要求する
- **安全制約**: Credential・個人情報に言及しないよう指示する
- **長さ制約**: 各セクション 100 字以内を指示する
- **役割定義**: 「あなたは AI ワークフローの状況アナリスト」として定義する

### 3.2 禁止事項（プロンプト内）

- ユーザーの個人情報・組織情報を含めない
- `node.config` の自由記述フィールドを含めない
- API キー・トークン・パスワードを含めない
- 外部 URL・エンドポイント情報を含めない

### 3.3 プロンプトのバージョン管理

- プロンプトテンプレートは `src/adapters/briefing/` 内に文字列定数として管理する
- プロンプトの変更は PR レビューを経ること
- プロンプトエンジニアリングの試行錯誤はブランチで行い、main へのマージ前に QA を実施する

## 4. 出力安全境界

### 4.1 出力検証

`BriefingAdapter.generate()` の戻り値は以下を検証する:

| チェック | 方法 |
|---|---|
| 型安全性 | `BriefingResult` 型に適合しているか確認 |
| 長さ制限 | 各セクションが 500 字を超えていないか確認 |
| 必須フィールド | `what`, `why`, `how`, `next` がすべて存在するか確認 |
| エスケープ | HTML インジェクションを防ぐため React の JSX テキストノードで表示する |

### 4.2 失敗時の挙動

- 型チェック失敗: エラーバナーを表示し、詳細ログはブラウザコンソールに出力する
- API タイムアウト（5 秒超過）: `タイムアウトしました` メッセージを表示し、mock モードへフォールバックするかどうかをユーザーに選択させる
- ネットワークエラー: `接続エラー: {message}` を表示する

## 5. mock モード運用

### 5.1 mock モードの明示

- mock ブリーフィングは必ず `isMock: true` フラグを保持する
- UI では「⚠ mock モード（実 AI API 未接続）」バナーを常時表示する
- mock バナーを非表示にする設定は提供しない

### 5.2 mock ブリーフィングの品質

- mock であっても、実際の入力データ（ログ数・エラー数・再試行候補数）を反映した動的テキストを生成する
- 「テストデータです」のような無意味なプレースホルダーは使用しない

---

## 6. 実 AI API 接続への移行条件

以下がすべて満たされた場合のみ ClaudeBriefingAdapter を有効にする:

1. Credential 管理方針が確定している（`docs/architecture/credential-safety-boundary.md` 参照）
2. ユーザーが明示的に API キーを設定している
3. API キーが localStorage / ログ / バンドルに保存されない実装になっている
4. プロンプトの QA が完了している
5. PR レビューが完了している
