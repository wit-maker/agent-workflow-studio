# 要件定義書 — 状況補佐官（完全版）

Last updated: 2026-05-26

> **概念修正の補助 SoT**: `docs/project/concept-layer-correction.md`（Issue #31）
> 本書の「状況補佐官」「状況説明生成レイヤー」「4D ブリーフィング」「text briefing MVP」は、同文書の定義に従って読むこと。

---

## 0. 用語

- **状況説明生成レイヤー**: ワークフロー実行状態を**過去・現在・未来の時間軸**で説明する後段レイヤー。
- **状況補佐官**: 状況説明生成レイヤーを**人間向けの役割として表現したもの**。単一 UI / 単一機能ではなく、後述する役割群を統合する。
- **4D ブリーフィング（What / Why / How / Next）**: 状況説明生成レイヤーの**出力チャネルの 1 つ**。テキスト・音声・アバター・動画・次アクション提示と並列のチャネル。
- **text briefing MVP**: 4D ブリーフィングのテキスト出力のみを扱う最小実装。状況補佐官の最終定義ではない。

---

## 1. 解く問題

Agent Workflow Studio でワークフローを実行すると、ログ・メトリクス・接続状態・エラー・ステップ証跡が大量に生成される。
ユーザーは「**過去**に何が起きたか」「**今**何が起きていて、なぜ止まったのか」「**これから**何が起きそうか」「次に何をすべきか」を、複数タブを横断して自分で解釈しなければならない。

**状況補佐官**は、この認知負荷を下げるために、ワークフロー状態を AI が**時間軸つき**で自動解釈し、人間向けの役割として提示するサービスである。

### 1.1 解決対象の認知コスト

| 問い | 現状のユーザー負担 |
|---|---|
| Past: 過去に何が起きたか | ログタブを遡って自分で時系列を組み立てる |
| What: 今何が起きているか | ログ・メトリクスを横断して読む |
| Why: なぜこの状態か | エラーメッセージを辿る、接続グラフを追う |
| Future: これから何が起きそうか | 過去の失敗パターンと現状を見比べる |
| How: どう対処するか | ドキュメントを調べる、自分で判断する |
| Next: 次のアクションは何か | 実行グラフ / 承認待ち / 再試行候補を見比べる |

これを **4D ブリーフィング（What / Why / How / Next）** などの出力チャネルで提示する。4D は**最小単位の出力チャネル**であり、状況補佐官全体ではない。

---

## 2. ゴール

1. Run 完了直後または任意のタイミングで、現在のワークフロー状態を時間軸つきの自然言語で説明できる。
2. エラー・警告・再試行候補・承認待ちを優先的に含む簡潔なブリーフィングを生成できる。
3. ユーザーが「次に何をすべきか」を 30 秒以内に把握できる。
4. 将来的に、テキストだけでなく音声・アバター・動画・動的ハイライトといった出力チャネルへ展開できる構造になっている。

---

## 3. MVP スコープと最終構想の分離

### 3.1 現在の MVP スコープ（text briefing MVP）

- 4D テキストブリーフィング（What / Why / How / Next）
- Mock アダプター（ネットワーク通信なし）
- BottomMonitor `ブリーフィング` タブによる読み取り表示
- Run Trace step evidence を含むサニタイズ済み入力

### 3.2 当面の MVP 非ゴール（最終構想からは削除しない）

以下は MVP スコープ外だが、**状況補佐官の当初発想**として削除・縮小せず、将来の出力チャネルとして扱う。

- 音声ブリーフィング（TTS）
- アバターによる説明
- ワークフロー状態のニュース風動画
- ワークフロー図の動的ハイライト映像
- リアルタイムストリーミング生成
- 外部 API・クラウドへのログ送信
- Credential / 機密情報の送信

### 3.3 状況補佐官の当初発想（必ず保持）

```text
自動でニュース動画を生成する仕組みが増えている。
それと同じ要領で、ワークフローやシステムの状態を自動で説明する動画を生成し、解説してもらう。
状況詳細・状況要約を、テキスト、音声、アバター、ビジュアル動画へ変換する。
時間軸（過去・現在・未来）で状況を説明できる。
ニュース動画、シミュレーションゲームの解説役、進行支援アバター、記事、音声、動画へ広く応用する。
```

状況補佐官は単なる「上位レイヤー」「指示役」「計画 AI」「TTS」「アバター」「動画生成機能」「ブリーフィングタブ」ではない。

---

## 4. ユーザー

| ユーザー種別 | 典型的な使い方 |
|---|---|
| ワークフロー設計者 | Run 後にブリーフィングを確認し、エラー原因・時系列・次アクションを把握する |
| 承認担当者（Human Review） | 確認待ちノードの過去経緯と影響範囲を把握してから判断する |
| 運用担当者 | 詰まり・コスト急増・複数 AI の判断割れを時間軸で振り返る |
| 開発者（将来） | 自動テスト・CI で状況サマリーを収集する |
| 解説アバター / ナレーター（将来） | シミュレーションゲーム風の進行支援、ニュース動画風の状況解説 |

## 5. 機能要件

### FR-01: 4D テキストブリーフィング生成（MVP）

- Run Log・Metrics・ExecutionGraph・ConnectorJob・Run Trace step evidence を入力とする。
- What / Why / How / Next の 4 次元で構造化したテキストを出力する。
- 1 回の生成で 400 字以内を目安とする。

### FR-02: オンデマンド生成（MVP）

- ユーザーが「ブリーフィングを生成」ボタンを押したときのみ生成する。
- 実行中の自動生成は MVP スコープ外。

### FR-03: HUD パネル表示（MVP）

- BottomMonitor 内の専用タブに表示する。
- 表示形式: テキスト + 重要度バッジ（info / warn / error）+ mock バナー + 生成日時。
- このタブは状況補佐官全体ではなく、**最小出力チャネルの表示先**である。

### FR-04: 入力ソース選択（MVP）

- 全ログ / 最新 Run のみ / エラーのみ を切り替えられる。

### FR-05: mock モード（MVP）

- 実 AI API 未接続の場合、固定テンプレートの mock ブリーフィングを返す。
- mock であることをバナーで明示する。

### FR-06: タイムラインナレーション（本来仕様、MVP スコープ外）

- 過去 → 現在 → 未来の時系列で出来事を整理し、ナレーション化する。

### FR-07: インシデントリプレイ（本来仕様、MVP スコープ外）

- 失敗・詰まり・承認待ちの起点から現在までを再生する。

### FR-08: マルチチャネル出力（本来仕様、MVP スコープ外）

- 4D テキスト以外に、Situation Summary / Situation Detail / Avatar Briefing / Audio Alert Briefing / Visual Explanation Render / Workflow News Video / Next Action Briefing を出力できる。

### FR-09: 役割切り替え（本来仕様、MVP スコープ外）

- 後述する役割群（コンシェルジュ / 秘書 / ナレーター / 報連相 / 状況参謀）に応じて、文体・粒度・出力チャネルを切り替えられる。

---

## 6. 非機能要件

| 属性 | 要件 |
|---|---|
| 安全境界 | Credential・個人情報・`node.config` 自由記述・raw payload をブリーフィング入力に含めない |
| 生成速度 | mock は即時、実 API は 5 秒以内（タイムアウト表示あり） |
| ローカル動作 | 実 API 未接続でも mock モードで動作する |
| 後方互換 | 既存のログ・メトリクス・ExecutionGraph 型を変更しない |
| 拡張性 | テキスト以外の出力チャネル（音声 / アバター / 動画 / 動的ハイライト）を後から追加できる基盤設計 |

---

## 7. 状況補佐官の役割群

状況補佐官は、単一の人格や単一 UI ではない。状況説明生成レイヤーを以下の役割群として人間向けに表現する。

| 役割 | 担うこと |
|---|---|
| コンシェルジュ | 次に見るべき場所 / 開くべきタブ / 確認すべきノードを案内する |
| 秘書 | 記録 / 要約 / 差分 / 履歴を整理して提示する |
| ナレーター | テキスト / 音声 / アバター / 動画で状況を説明する |
| 報連相エージェント | 報告 / 連絡 / 相談として状態変化を上げる |
| 状況参謀 | 過去・現在・未来を整理し、リスクと次アクションを提示する |

UI 上の中心名称は「状況補佐官」、設計上の機能カテゴリ名は「状況説明生成レイヤー」「4D 状況説明エディタ」「Workflow Situation Narration Layer」とする。

---

## 8. 状況補佐官が説明できるべき問い

```text
- 過去に何が起きたか
- 現在どこで止まっているか
- 未来に何が起きそうか
- なぜこうなったか
- いつからおかしくなったか
- どこが原因か
- 今は止めるべきか / 進めてよいか
- 次に誰が何を判断すべきか
- この失敗は前にもあったか
- 次回どう防ぐか
```

---

## 9. 認知HUD との関係

状況補佐官は認知HUDの上位管理者ではない。両者は変換パイプライン上の隣接レイヤーである。

```text
ワークフロー実行状態
  → 観測
    → 認知HUDによる注意配分        ← 注意配分編集レイヤー
      → 状況説明生成              ← 状況補佐官が担う領域
        → テキスト / 音声 / アバター / 動画 / 次アクション
```

認知HUDは「人間がその瞬間に見るべき情報を選別・圧縮・強調・通知・介入へ変換する」。
状況補佐官は「認知HUDで選別・圧縮された情報、Run Trace、ログ、メトリクス、成果物、履歴を材料にして、時間軸つきの説明へ変換する」。

## 10. 制約

- `docs/source-specs/` の本体仕様（01〜07）の概念定義と、`docs/project/concept-layer-correction.md` の概念定義は整合させる。衝突時は概念修正文書を優先する。
- 現在の text briefing MVP は状況補佐官の最終定義ではない。MVP 表示面に最終仕様を縮小しない。
- 音声・アバター・動画の応用可能性は、本書および後続文書から削除しない。
- Tauri / SQLite / Zustand / 外部認証は MVP スコープ外。
