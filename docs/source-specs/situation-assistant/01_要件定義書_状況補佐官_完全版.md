# 要件定義書 — 状況補佐官（完全版）

Last updated: 2026-05-25

---

## 1. 解く問題

Agent Workflow Studio でワークフローを実行すると、ログ・メトリクス・接続状態・エラーが大量に生成される。
ユーザーは「今何が起きているのか」「なぜ止まったのか」「次に何をすべきか」を、複数タブを横断して自分で解釈しなければならない。

**状況補佐官**は、この認知負荷を下げるために、実行状態を AI が自動解釈してテキストで説明するサービスである。

### 解決対象の認知コスト

| 問い | 現状のユーザー負担 |
|---|---|
| What: 今何が起きているか | ログタブを読む、メトリクスを数える |
| Why: なぜこの状態か | エラーメッセージを辿る、接続グラフを追う |
| How: どう対処するか | ドキュメントを調べる、自分で判断する |
| Next: 次のアクションは何か | 実行グラフと再試行候補を見比べる |

これを **4D ブリーフィング（What / Why / How / Next）** として一画面に要約する。

---

## 2. ゴール

1. Run 完了直後または任意のタイミングで、現在のワークフロー状態を自然言語で説明できる。
2. エラー・警告・再試行候補を優先的に含む簡潔なブリーフィングを生成できる。
3. ユーザーが「次に何をすべきか」を 30 秒以内に把握できる。

---

## 3. 非ゴール（MVP スコープ外）

- 音声ブリーフィング（TTS）
- 動画・アバター生成
- リアルタイムストリーミング（実行中の逐次更新）
- 外部 API・クラウドへのログ送信
- Credential / 機密情報の送信

---

## 4. ユーザー

| ユーザー種別 | 典型的な使い方 |
|---|---|
| ワークフロー設計者 | Run 後にブリーフィングを確認し、エラー原因を素早く把握する |
| 承認担当者（Human Review） | 確認待ちノードの背景状況を把握してから判断する |
| 開発者（将来） | 自動テスト・CI で状況サマリーを収集する |

---

## 5. 機能要件

### FR-01: 4D ブリーフィング生成

- Run Log・Metrics・ExecutionGraph・ConnectorJob を入力とする。
- What / Why / How / Next の 4 次元で構造化したテキストを出力する。
- 1 回の生成で 400 字以内を目安とする（長いブリーフィングは折りたたみ表示）。

### FR-02: オンデマンド生成

- ユーザーが「ブリーフィングを生成」ボタンを押したときのみ生成する。
- 実行中の自動生成は MVP スコープ外。

### FR-03: HUD パネル表示

- BottomMonitor 内の専用タブまたは既存 HUD パネルに表示する。
- 表示形式: テキスト + 重要度バッジ（info / warn / error）。

### FR-04: 入力ソース選択

- 全ログ / 最新 Run のみ / エラーのみ を切り替えられる。

### FR-05: mock モード

- 実 AI API 未接続の場合、固定テキストの mock ブリーフィングを返す。
- mock であることをバナーで明示する。

---

## 6. 非機能要件

| 属性 | 要件 |
|---|---|
| 安全境界 | Credential・個人情報をブリーフィング入力に含めない |
| 生成速度 | mock は即時、実 API は 5 秒以内（タイムアウト表示あり） |
| ローカル動作 | 実 API 未接続でも mock モードで動作する |
| 後方互換 | 既存のログ・メトリクス・ExecutionGraph 型を変更しない |
