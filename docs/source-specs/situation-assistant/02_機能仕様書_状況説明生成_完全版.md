# 機能仕様書 — 状況説明生成（完全版）

Last updated: 2026-05-26

> **概念修正の補助 SoT**: `docs/project/concept-layer-correction.md`（Issue #31）
> 4D ブリーフィングは状況説明生成レイヤーの**出力チャネルの 1 つ**であり、状況補佐官の全体ではない。

---

## 1. 概要

状況説明生成は、Agent Workflow Studio の実行状態データを入力として、人間向けの**状況説明**を生成する機能群である。

現在の MVP は **4D テキストブリーフィング** のみを実装する。本書はその仕様と、後続の出力チャネルおよびサブ機能を定義する。

---

## 2. 入力データ仕様

### 2.1 入力ソース一覧

| ソース | 型 | 収集タイミング |
|---|---|---|
| Run Log | `RunLog[]` | 最新 Run 完了後 |
| Metrics | `WorkflowMetrics` | 最新 Run 完了後 |
| ExecutionGraph | `ExecutionGraph \| null` | 最新 Run 完了後 |
| ConnectorJob 一覧 | `ConnectorJob[]` | 現在の queue 状態 |
| Workflow 構造 | `Workflow` | 現在の状態 |
| Run Trace Step Evidence | `RunDetailSummary` | 最新 Run の各ステップ証跡（サニタイズ済み） |
| HUD Snapshot | `HudSnapshot` | 現在の認知HUDサマリ |
| Run History（将来） | `WorkflowRunRecord[]` | 過去実行を参照する場合 |

### 2.2 入力フィルタリング

- Credential 値・APIキー・パスワードを含む可能性のあるフィールドは除外する。
- `node.config` 内の自由記述フィールドは除外する。
- 最大入力トークン数を超える場合は最新エントリを優先して切り詰める。
- `password` / `token` / `key` / `secret` / `apiKey` / `credential` / `authorization` / `bearer` を含む文字列は大文字小文字無視で除外する。

## 3. サブ機能一覧

状況説明生成レイヤーは、以下のサブ機能群で構成される。**現在 MVP では 4D テキストブリーフィングのみ**を実装している。

| サブ機能 | 役割 | MVP 状態 |
|---|---|---|
| Situation Summary | 現在状況を短く要約する | 部分実装（4D の What に含む） |
| Situation Detail | 詳細な状況説明を生成する | 部分実装（4D の Why に含む） |
| Timeline Narration | 過去 → 現在 → 未来を時系列で説明する | 未実装 |
| Incident Replay | 失敗・詰まり・承認待ちを再生する | 未実装 |
| Workflow News Video | ワークフロー状態をニュース風に動画化する | 未実装 |
| Avatar Briefing | アバターが状況を説明する | 未実装 |
| Audio Alert Briefing | 音声で重要変化を知らせる | 未実装（Critical 短音通知は認知HUD 側の表現チャネル） |
| Visual Explanation Render | ノード / エッジ / ログ / メーターを動的にハイライトする | 未実装 |
| Next Action Briefing | 次に人間が見るべき場所・判断すべきことを説明する | 部分実装（4D の Next に含む） |

これらは並列の出力チャネルであり、相互に縮小・代替しない。

## 4. 4D テキストブリーフィング構造（MVP の最小出力チャネル）

```
## What（何が起きているか）
現在のワークフロー状態・実行結果のサマリー。

## Why（なぜこの状態か）
エラー・警告の根拠となるログ・接続状態・ステップ証跡の解釈。

## How（どう対処するか）
再試行・Human Review・修正候補などの推奨アクション。

## Next（次のステップ）
ユーザーが取るべき最優先アクション 1〜3 件。
```

### 4.1 重要度バッジ

各セクションに重要度を付与する:

| バッジ | 条件 |
|---|---|
| `info` | 正常完了、情報のみ |
| `warn` | 警告あり、要確認 |
| `error` | エラー・失敗あり、要対処 |

## 5. 生成フロー

### 5.1 MVP（テキスト出力）

```
[ユーザー操作: 生成ボタン押下]
        ↓
[入力収集: Log / Metrics / Graph / Jobs / RunTrace / HUD]
        ↓
[フィルタリング: Credential除外 / node.config除外 / payload除外]
        ↓
[プロンプト構築]
        ↓
[AI 呼び出し / mock 返却]
        ↓
[レスポンス検証: 長さ・構造チェック]
        ↓
[HUD パネルへテキスト表示]
```

### 5.2 本来仕様（マルチチャネル出力、MVP スコープ外）

```
[ユーザー操作 or 自動トリガ]
        ↓
[入力収集 / フィルタリング]
        ↓
[Timeline Extractor]          重要イベント列を抽出
        ↓
[Situation Summarizer]        状況要約
        ↓
[Cause Analyzer]              原因候補
        ↓
[Future Risk Predictor]       未来リスク
        ↓
[Briefing Script Writer]      解説台本生成
        ↓
┌───────────┬────────────┬──────────────┬───────────────┐
↓           ↓            ↓              ↓               ↓
Text 4D    Voice       Avatar        Visual          Workflow
Briefing   Generator   Narrator      Highlight       News Video
                                     Renderer        Composer
        ↓
[Human Decision Prompt]       次アクション提示
```

## 6. 追加候補ノードカテゴリ「説明・ブリーフィング」

状況説明生成レイヤーは、本体機能仕様書（`02_機能仕様書_完全版.md`）のノードカテゴリに **「説明・ブリーフィング」** を追加することを推奨する。代表ノードは以下。

| ノード | 役割 |
|---|---|
| Timeline Extractor | Run Log / Trace から重要イベント列を抽出する |
| Situation Summarizer | Metrics / Logs / Errors から状況要約を作る |
| Cause Analyzer | Error / Trace / Diff から原因候補を作る |
| Future Risk Predictor | 現在状態 / 過去失敗から未来リスクを推定する |
| Briefing Script Writer | 要約 / 原因 / 次アクションから解説台本を作る |
| Avatar Narrator | 解説台本をアバター説明へ変換する |
| Voice Generator | 解説台本を音声へ変換する |
| Visual Highlight Renderer | Workflow State をハイライト映像へ変換する |
| Briefing Video Composer | 音声 / 図解 / アバターから状況説明動画を構成する |
| Human Decision Prompt | 状況説明から承認 / 却下 / 再実行の選択肢を提示する |

これらは MVP スコープ外だが、最終構想として削除・縮小しない。

## 7. 動画化・音声化すべき対象（運用ポリシー）

すべてを動画化・音声化してはいけない。動画化や音声化は認知負荷を増やす可能性がある。

動画化・音声化・アバター化すべき対象は、原則として以下である。

```text
失敗した実行
承認待ちで止まった実行
コストが急増した実行
詰まりが発生した実行
複数AIの判断が割れた実行
重要なテンプレート候補になった成功実行
人間の判断が必要な状態
長時間放置後の再開時
```

通常の細かい成功ログまで毎回動画化する必要はない。

## 8. プロンプト仕様（MVP）

### 8.1 システムプロンプト（概要）

```text
あなたは AI ワークフローの状況を、過去・現在・未来の時間軸で分析し、
日本語の簡潔なブリーフィングを提供する状況補佐官の役割を担います。
入力は Agent Workflow Studio の実行ログ・メトリクス・実行グラフ・
ステップ証跡・HUD サマリです。
出力は What / Why / How / Next の 4 セクションで構成してください。
各セクションは 100 字以内。Credential・APIキー・個人情報には言及しない。
```

### 8.2 入力テンプレート

```text
# ワークフロー状態

ワークフロー名: {workflow.name}
実行モード: {executionMode}
最終ステータス: {overallStatus}

## 実行ログ（最新 {N} 件）
{logs}

## メトリクス
{metrics}

## エラー・警告
{errors}

## ステップ証跡（サニタイズ済み）
{stepEvidence}

## 再試行候補
{retryCandidates}

## 認知HUD サマリ
{hudSummary}
```

## 9. mock ブリーフィング仕様

実 API 未接続時は、入力統計値を反映した動的テンプレートテキストを返す:

```text
## What
{N} ノードが実行されました。{successCount} 件成功、{errorCount} 件エラーです。

## Why
{topError または「エラーなし」}

## How
{retryCandidates がある場合: 「再試行候補があります。再試行ボタンで再実行できます。」}
{retryCandidates がない場合: 「特別な対処は不要です。」}

## Next
{nextAction: 最優先アクション}

---
⚠ これは mock ブリーフィングです。実 AI API は未接続です。
```

## 10. 表示仕様

### 10.1 BottomMonitor タブ

- タブ名: `ブリーフィング`
- このタブは状況補佐官全体ではなく、4D テキスト出力チャネルの表示先である。
- 既存タブ（ログ / メトリクス / キュー / 出力 / 実行グラフ / 評価 / エージェント / ストレージ / Roadmap / 認知HUD / 実行詳細）に干渉しない。

### 10.2 表示要素

```
[生成ボタン]  [入力ソース選択: 全ログ / 最新のみ / エラーのみ]

─────────────────────────────
📋 ブリーフィング  [info/warn/error バッジ]  生成日時

## What
...

## Why
...

## How
...

## Next
...
─────────────────────────────
⚠ mock モード（実 API 未接続）  ← 実 API 未接続時のみ表示
```

### 10.3 生成中表示

- スピナー + 「生成中...」テキスト
- キャンセルボタン

### 10.4 エラー表示

- 生成失敗時: `ブリーフィング生成に失敗しました: {error}` を赤バナーで表示
- タイムアウト時: `タイムアウトしました。入力データを減らして再試行してください。`

## 11. 状態管理

```typescript
type BriefingState = {
  status: 'idle' | 'generating' | 'done' | 'error'
  brief: BriefingResult | null
  error: string | null
  generatedAt: string | null  // ISO date string
  inputMode: 'all' | 'latest-run' | 'errors-only'
}

type BriefingResult = {
  what: string
  why: string
  how: string
  next: string
  severity: 'info' | 'warn' | 'error'
  isMock: boolean
}
```

状態は React state として保持する。localStorage への永続化は MVP スコープ外。
