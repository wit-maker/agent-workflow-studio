## 1. 受け入れ基準（MVP）

### AC-01: ブリーフィングタブ表示

- [ ] BottomMonitor に「ブリーフィング」タブが表示される
- [ ] タブをクリックするとブリーフィングパネルに切り替わる
- [ ] 既存タブ（ログ / メトリクス / キュー / 出力 / 実行グラフ / 評価 / エージェント / ストレージ / Roadmap）の表示が壊れていない

### AC-02: 空状態

- [ ] 初回表示時に「ブリーフィングはまだ生成されていません」メッセージが表示される
- [ ] 生成ボタンが有効になっている

### AC-03: mock ブリーフィング生成

- [ ] 「ブリーフィングを生成」ボタンを押すと生成が開始される
- [ ] 生成中はスピナーが表示される
- [ ] 生成完了後に 4D ブリーフィング（What / Why / How / Next）が表示される
- [ ] 「⚠ mock モード（実 AI API 未接続）」バナーが表示される
- [ ] 重要度バッジ（info / warn / error）が表示される

### AC-04: 入力ソース切り替え

- [ ] 「全ログ」「最新 Run のみ」「エラーのみ」を選択できる
- [ ] 切り替え後に再生成すると異なる内容が表示される（mock でも統計値が変わる）

### AC-05: Run All との連携

- [ ] Run All 実行後にブリーフィングを生成すると、実行結果が反映される
- [ ] Run 前と Run 後でブリーフィング内容が異なる

### AC-06: エラー表示

- [ ] 生成失敗時にエラーバナーが表示される
- [ ] エラー後も再生成ボタンが有効になる

### AC-07: console エラーなし

- [ ] ブリーフィングタブ操作中に console error が発生しない

## 2. セキュリティ要件

### SEC-01: Credential 除外

- [ ] `BriefingInputCollector` が `node.config` を除外することをユニットテストで確認する
- [ ] `password`, `token`, `key`, `secret`, `apiKey` を含む文字列がプロンプトに含まれないことを確認する

### SEC-02: mock モードのネットワーク通信なし

- [ ] MockBriefingAdapter 使用時にネットワークリクエストが発生しないことをブラウザ DevTools で確認する

### SEC-03: XSS 防止

- [ ] ブリーフィングテキストが React JSX テキストノードとしてレンダリングされる（`innerHTML` を使用しない）
- [ ] マークダウンレンダリングを使用する場合は DOMPurify または同等のサニタイズを適用する

### SEC-04: ローカルストレージへの Credential 保存なし

- [ ] BriefingState が localStorage に永続化されていないことを確認する（MVP は React state のみ）

## 4. 停止条件（Do Not）

以下を検出した場合は実装を止め、ユーザーに報告すること:

- Credential 値がプロンプトに含まれる可能性が生じた場合
- `BriefingState` を localStorage に永続化しようとする設計になった場合
- 本体仕様（`docs/source-specs/01〜07`）の変更が必要になった場合
- 実 AI API 接続の実装を MVP に含めようとする場合
- PR #20 に状況補佐官の実装コードを混ぜようとする場合

## 5. 既知の制限（MVP）

| 制限 | 理由 | 将来対応 |
|---|---|---|
| mock のみ | 実 API Credential 管理未確定 | Phase 2 で ClaudeBriefingAdapter 追加 |
| 生成履歴なし | durable run history が未実装 | Phase 3 で連動 |
| 実行中の自動生成なし | リアルタイムストリーミング未実装 | Phase 4 |
| file picker で生成履歴を export できない | MVP スコープ外 | Phase 3 |
