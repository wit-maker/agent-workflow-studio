## 1. 概念整合の受け入れ基準（全フェーズ共通）

### CC-01: 認知HUD の定義整合

- [ ] ドキュメント中で認知HUD が「HUDタブ」「下部モニターの状態一覧」「テキスト要約」と等値で説明されていない
- [ ] 認知HUD が「注意配分編集レイヤー / 状況認識編集レイヤー / 意思決定支援レイヤー」として記述されている
- [ ] Critical 短音通知などの音が、認知HUDの表現チャネルとして残されている

### CC-02: 状況補佐官の定義整合

- [ ] 状況補佐官が「ブリーフィングタブ」「TTS」「アバター」「動画生成だけ」「計画 AI」のいずれかと等値で説明されていない
- [ ] 状況補佐官が「状況説明生成レイヤーを人間向けの役割として表現したもの」として記述されている
- [ ] 状況補佐官の役割群（コンシェルジュ / 秘書 / ナレーター / 報連相 / 状況参謀）が削除されていない

### CC-03: text briefing MVP の位置づけ

- [ ] text briefing MVP が「状況補佐官全体」ではなく「状況説明生成レイヤーの最小出力チャネルの 1 つ」として記述されている
- [ ] 4D ブリーフィングが、音声 / アバター / 動画 / 次アクションと並列の出力チャネルとして記述されている

### CC-04: 時間軸の整合

- [ ] 状況説明生成レイヤーが「過去・現在・未来の時間軸で説明する」と明記されている
- [ ] 状況補佐官が「今この瞬間だけを見る AI」として説明されていない

### CC-05: 出力チャネルの保持

- [ ] 音声・アバター・動画・動的ハイライト・ニュース風動画が、出力チャネルとして削除・縮小されていない
- [ ] MVP スコープ外であることと、概念から削除することが混同されていない

## 2. 受け入れ基準（MVP: text briefing）

### AC-01: ブリーフィングタブ表示

- [ ] BottomMonitor に「ブリーフィング」タブが表示される
- [ ] タブをクリックするとブリーフィングパネルに切り替わる
- [ ] 既存タブ（認知HUD / 実行詳細 / ログ / メトリクス / キュー / 出力 / 実行グラフ / 評価 / エージェント / ストレージ / Roadmap）の表示が壊れていない
- [ ] このタブが「状況補佐官全体ではなく 4D テキスト出力チャネルの表示先である」ことを UI または近傍ドキュメントから読み取れる

### AC-02: 空状態

- [ ] 初回表示時に「ブリーフィングはまだ生成されていません」メッセージが表示される
- [ ] 生成ボタンが有効になっている

### AC-03: mock ブリーフィング生成

- [ ] 「ブリーフィングを生成」ボタンを押すと生成が開始される
- [ ] 生成中はスピナーが表示される
- [ ] 生成完了後に 4D ブリーフィング（What / Why / How / Next）が表示される
- [ ] 「⚠ mock モード（実 AI API 未接続）」バナーが表示される
- [ ] 重要度バッジ（info / warn / error）が表示される

### AC-04: 入力ソース切り替え

- [ ] 「全ログ」「最新 Run のみ」「エラーのみ」を選択できる
- [ ] 切り替え後に再生成すると異なる内容が表示される（mock でも統計値が変わる）

### AC-05: Run All との連携

- [ ] Run All 実行後にブリーフィングを生成すると、実行結果が反映される
- [ ] Run 前と Run 後でブリーフィング内容が異なる

### AC-06: エラー表示

- [ ] 生成失敗時にエラーバナーが表示される
- [ ] エラー後も再生成ボタンが有効になる

### AC-07: console エラーなし

- [ ] ブリーフィングタブ操作中に console error が発生しない

### AC-08: 認知HUD タブとの混同なし

- [ ] BottomMonitor の `認知HUD` タブと `ブリーフィング` タブが別の役割を持っていることが UI から区別できる（前者は注意配分サマリ、後者は時間軸つきテキスト説明）

## 3. セキュリティ要件

### SEC-01: Credential 除外

- [ ] `BriefingInputCollector` が `node.config` を除外することをユニットテストで確認する
- [ ] `password`, `token`, `key`, `secret`, `apiKey`, `credential`, `authorization`, `bearer` を含む文字列がプロンプトに含まれないことを確認する

### SEC-02: mock モードのネットワーク通信なし

- [ ] MockBriefingAdapter 使用時にネットワークリクエストが発生しないことをブラウザ DevTools で確認する

### SEC-03: XSS 防止

- [ ] ブリーフィングテキストが React JSX テキストノードとしてレンダリングされる（`innerHTML` を使用しない）
- [ ] マークダウンレンダリングを使用する場合は DOMPurify または同等のサニタイズを適用する

### SEC-04: ローカルストレージへの Credential 保存なし

- [ ] BriefingState が localStorage に永続化されていないことを確認する（MVP は React state のみ）

### SEC-05: 役割逸脱の検出

- [ ] 出力に「ワークフローを書き換えました」「自動実行しました」などの計画 / 実行側の宣言が含まれていないか検証する

## 5. 停止条件（Do Not）

以下を検出した場合は実装を止め、ユーザーに報告すること:

- Credential 値がプロンプトに含まれる可能性が生じた場合
- `BriefingState` を localStorage に永続化しようとする設計になった場合
- 本体仕様（`docs/source-specs/01〜07`）と概念修正文書を同時に矛盾させる変更が必要になった場合
- 実 AI API 接続の実装を MVP に含めようとする場合
- 状況補佐官を ブリーフィングタブ / TTS / アバター / 動画生成のいずれか単独に**縮小**しようとする場合
- 認知HUDを HUDタブ / 単一パネルに**縮小**しようとする場合
- 音声・アバター・動画の応用可能性を**削除**しようとする場合

## 6. 既知の制限（MVP）

| 制限 | 理由 | 将来対応 |
|---|---|---|
| mock のみ | 実 API Credential 管理未確定 | Phase 2 で ClaudeBriefingAdapter 追加 |

| テキスト出力のみ | 音声 / アバター / 動画 / 動的ハイライトは Phase 6 以降 | 当初発想として概念削除しない |
| Timeline Narration / Incident Replay 未実装 | サブ機能群が Phase 5 以降 | 機能仕様書 §3 参照 |
