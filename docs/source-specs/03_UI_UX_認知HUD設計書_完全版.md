# Agent Workflow Studio UI/UX・認知HUD設計書 完全版

> **概念修正の補助 SoT**: `docs/project/concept-layer-correction.md`（Issue #31）
> 認知HUD は HUDタブではなく、**注意配分編集レイヤー / 状況認識編集レイヤー / 意思決定支援レイヤー**である。本書はこの定義に従って読むこと。

---

## 1. UI原則

Agent Workflow Studio のUIは、全部を表示するUIではなく、人間が今見るべき情報を優先表示するUIである。

認知HUDは、情報を増やすUIではない。AIワークフローの大量状態を、人間がその瞬間に見るべき情報へ**選別・圧縮・強調・通知・介入**として変換する。

---

## 2. 認知HUDの定義

### 2.1 認知HUDとは何か

認知HUDは、以下のいずれかではない。

- HUDタブ
- 下部モニターの状態一覧
- ログやメトリクスの要約パネル
- 画面の一部にテキストを表示する機能
- 単なる「視界」

認知HUDは以下である。

```text
注意配分編集レイヤー
状況認識編集レイヤー
意思決定支援レイヤーエディタ
```

認知HUDは、ワークフローの大量状態を、人間が扱える注意設計へ変換する変換器である。

```text
選別  ── どの情報を残し、どの情報を捨てるか
圧縮  ── 残した情報をどう短くするか
強調  ── どれをどの強さで前に出すか
通知  ── どの瞬間に注意を移してもらうか
介入  ── どの場合に操作の手前で止めるか
```

### 2.2 認知HUDが設計する 5 つの次元

認知HUDは、以下の 5 つの問いを設計する。

```text
何を見せるか
いつ見せるか
どこに見せるか
どのように見せるか
どの程度見せるか
```

### 2.3 表現チャネル

認知HUDは、上記の設計を以下の表現チャネル群で実現する。

```text
色 / 形 / 透明度 / 明滅 / 線の太さ / 線の速度
アイコン / ラベル / 音 / 奥行き / タイムライン
フォーカス / 減光 / 通知 / 介入カード / モーダル
```

**音** を認知HUDの概念から除外してはいけない。Critical 時の短音通知は、視線を強制せずに注意を移す有効な注意喚起チャネルである。

ただし、これは「全情報を音声化する」「全情報を TTS 化する」ことではない。常時 TTS 化は認知負荷を増やすため、認知HUDの本質ではない。音声化・動画化・アバター化は、状況説明生成レイヤー側で、必要な場面に限って行う出力チャネルである。

## 3. 認知HUDの状態

| Level | 状態 |
|---|---|
| L0 | 通常 |
| L1 | 注意 |
| L2 | 遅延 / 詰まり |
| L3 | 失敗 |
| L4 | 人間承認待ち |
| L5 | 危険操作 / 実行停止 |

状態は、選別・圧縮・強調・通知・介入の閾値を決める入力である。L0〜L2 は減光・サマリ寄り、L3 以上はフォーカス・通知・介入カードへ重みを移す。

---

## 4. 表示要素（注意配分の出力面）

これらは認知HUDの構成要素であり、画面のどこか 1 箇所のパネルではない。Canvas / Inspector / BottomMonitor / Top Bar / モーダルに分散して現れる。

- Focus Lens — 今見るべき箇所だけを明るく保つ
- Alert Layer — 危険・失敗・承認待ちを前面に出す
- Minimap Warning — 視界外の異常を地図側で示す
- Bottleneck Highlight — 詰まり箇所を強調する
- Human Review Spotlight — 承認待ちを見落とさせない
- Audio Cue — Critical のみの短音通知
- Depth Layer — 重要度に応じた奥行き / 減光
- Auto Hide / Reveal — 不要情報を一時的に隠す / 戻す
- HUD Badge — ノード / 接続上に出る重要度バッジ
- Center HUD Card — 画面中央に出す決定的状況カード
- Approval Pending HUD — 承認待ち専用の集約カード
- Failure Cause Card — 失敗原因をたどれるカード
- Focus Overlay — 注目すべき経路だけを浮かせる
- Path Dim — 不要経路を減光する
- Notification Bundle — 短時間の通知をまとめて 1 件にする
- HUD History — 過去の HUD 表示を後追いできる履歴

## 5. 画面責任

| 領域 | 役割 |
|---|---|
| Top Bar | 保存、実行、停止、検証、状態 |
| Left Sidebar | 部品、テンプレ、検索 |
| Canvas | ノード、接続、流量、HUDバッジ、フォーカス、減光 |
| Inspector | 設定、ポート、テスト、リスク |
| Bottom Monitor | ログ、キュー、メトリクス、成果物、HUDサマリ、状況説明（出力チャネル） |
| Stage | 成果物プレビュー、承認、差分 |

> Bottom Monitor 内のタブ（HUD タブ / ブリーフィングタブ など）は、認知HUD本体ではなく、HUD サマリ・シグナル一覧・状況説明出力を**詳細確認できる補助領域**である。本体は Canvas / Inspector / モーダル / 通知を含めた全画面に分散する注意設計そのものである。

## 6. 現在の MVP 表示面と本来仕様

現在 MVP には以下の暫定表示面が存在する。これらは認知HUD本体ではなく、HUD の一部を読みやすく集約した補助領域である。

| 現在の MVP 表示面 | 位置づけ |
|---|---|
| BottomMonitor `認知HUD` タブ | HUD サマリ / シグナル一覧を一覧できる補助タブ |
| `CognitiveHudPanel` コンポーネント | 上記タブの実体。本来は `HudSummaryPanel` / `HudSignalList` のように、HUD 本体ではなくサマリ表示と分かる命名が望ましい |
| BottomMonitor `ブリーフィング` タブ | 状況説明生成レイヤーの最小出力チャネル（テキスト 4D ブリーフィング） |
| BottomMonitor `実行詳細` タブ | Run Trace step evidence を読み取り専用で見せる補助タブ |

本来仕様としてはまだ未実装の主要要素は次のとおり（詳細は `docs/audit/missing-systems.md` 参照）。


## 7. 状況説明生成レイヤーとの関係

認知HUDは、選別・圧縮・強調された情報を提供する。状況説明生成レイヤーは、その情報と Run Trace / ログ / メトリクス / 成果物 / 履歴を材料に、**過去・現在・未来の時間軸つきの説明**へ変換する後段レイヤーである。

```text
ワークフロー実行状態
  → 観測
    → 認知HUDによる注意配分        ← 本書の対象
      → 状況説明生成              ← situation-assistant/ 配下の対象
        → テキスト / 音声 / アバター / 動画 / 次アクション
```

状況補佐官は、状況説明生成レイヤーを人間向けの役割として表現したものであり、認知HUDの上位管理者ではない。両者は変換パイプライン上の隣接レイヤーである。

## 8. UX禁止事項

- 重要警告をログだけに隠す
- 色だけで危険度を伝える
- 失敗したノードへ移動できない
- 承認待ちと失敗を同じ見た目にする
- Credential関連の警告を弱く表示する
- 認知HUDを HUDタブや 1 つのパネルに閉じ込める
- すべての通知を音声化・動画化して認知負荷を増やす
- HUD バッジ / フォーカス / 減光 / 介入カードといった本来仕様を、暫定サマリパネルだけで代替したと見なす
