# 認知HUD / 状況説明生成レイヤー / 状況補佐官 概念修正文書

Issue #31 の内容を、プロジェクト内で参照できる Source of Truth 補助文書として保存する。

この文書は、現在のMVP実装に仕様を合わせるためのものではない。Agent Workflow Studio の最終構想に対して、認知HUD、状況説明生成レイヤー、状況補佐官の概念ズレを防ぐための基準である。

---

## 1. なぜ修正が必要か

現在の実装はMVPであり、HUDタブ、状態サマリー、シグナル一覧、ブリーフィングタブなどの足場が中心である。

しかし、これらをそのまま最終仕様として説明すると、以下の誤解が起きる。

```text
認知HUD = HUDタブ
認知HUD = 下部モニターの状態一覧
認知HUD = ログやメトリクスの要約パネル
状況補佐官 = ブリーフィングタブ
状況補佐官 = TTS / アバター / 動画生成だけ
状況補佐官 = 上位管理者や計画役
```

正しくは、認知HUDは「人間の注意配分を設計するレイヤー」であり、状況補佐官は「状況説明生成レイヤーを人間向けの役割として表現したもの」である。

---

## 2. 正しい変換パイプライン

単純に「補佐官 → 認知HUD → Upload Labs風 → n8n風 → Scratch風」とだけ説明すると、補佐官が単なる上位管理者に見えるため不十分である。

正しくは、以下の変換パイプラインとして扱う。

```text
Scratch風操作レイヤー
  → 最小単位の部品を組み合わせる

n8n風自動化レイヤー
  → 内部/外部ツール、AI、API、ファイル、条件分岐、Retry、Human Reviewを接続する

Upload Labs風インフラ観測レイヤー
  → 流量、資源、詰まり、負荷、遅延、コスト、キュー、ボトルネックを観測する

認知HUDレイヤー
  → 大量状態を、人間の注意配分に合わせて選別・圧縮・強調・通知・介入へ変換する

状況説明生成レイヤー
  → 過去・現在・未来の時間軸で、何が起きたか、なぜそうなったか、次に何が起きそうかを説明する

出力チャネル
  → テキスト、記事、音声、アバター、ビジュアル動画、ニュース風動画、ブリーフィングカード、次アクション提示
```

短縮形は以下とする。

```text
ワークフロー実行状態
  → 観測
    → 認知HUDによる注意配分
      → 状況説明生成
        → テキスト / 音声 / アバター / 動画 / 次アクション
```

## 3. Agent Workflow Studio の正しいプロダクト定義

```text
Scratch風ビジュアルプログラミングエディタ
+ n8n風ビジュアルワークフロー自動化エディタ
+ Upload Labs風ビジュアル・システムフロー編集エディタ
+ 認知HUD風注意配分編集エディタ
+ 状況説明生成レイヤー

```

リポジトリ内ドキュメントでは、以下を必ず分ける。

```text
最終構想 / 目指すアーキテクチャ
と
現在のMVP / 暫定表示面 / 実装足場
```

## 4. 各レイヤーの定義

### 4.1 Scratch風レイヤー

Scratch風は、最小単位の部品をブロックのように組み合わせる、ビジュアルプログラミング的な操作層である。

単なる子ども向けの見た目ではない。

Agent Workflow Studio では、以下のような最小ワークフロー部品を扱う。

```text
入力
整形
AI実行
検査
承認
保存
テンプレート化
再利用可能な小さなワークフロー部品
```

### 4.2 n8n風レイヤー

n8n風は、内部ツール、外部ツール、AI、ファイル、API、実行条件、分岐、Retry、Error Route、Human Review、Adapter境界を接続し、自動化フローとして流す層である。

単にノードが線でつながっている表示ではない。

### 4.3 Upload Labs風レイヤー

Upload Labs風は、インフラ的・システムフロー的な状態を見える化する層である。

単なるメトリクス表ではない。

対象は以下である。

```text
流量
資源圧力
詰まり
負荷
遅延
コスト
トークン
キュー
ボトルネック
成功率
失敗率
外部接続状態
```

### 4.4 認知HUDレイヤー

認知HUDは、HUDタブ、テキスト要約、ログパネル、下部モニター、画面の一部にテキストを表示する領域ではない。

認知HUDは以下である。

```text
注意配分編集エディタ
状況認識編集エディタ
意思決定支援レイヤーエディタ
```

認知HUDは、AIワークフローの大量状態を、人間が扱える注意設計へ変換する。

```text
選別
圧縮
強調
通知
介入
```

認知HUDは以下の5つを設計する。

```text
何を見せるか
いつ見せるか
どこに見せるか
どのように見せるか
どの程度見せるか
```

表現チャネルには以下を含む。

```text
色
形
透明度
明滅
線の太さ
線の速度
アイコン
ラベル
音
奥行き
タイムライン
フォーカス
減光
通知
介入カード
モーダル
```

音を認知HUDの概念から除外してはいけない。Critical時の短音通知は、注意喚起チャネルとして有効である。

ただし、これはすべての情報を音声化することや、全情報をTTS化することとは別である。常時TTS化は、むしろ認知負荷を増やす可能性があり、認知HUDの本質ではない。

### 4.5 状況説明生成レイヤー / 状況補佐官

状況説明生成レイヤーは、認知HUDで選別・圧縮・強調された情報、Run Trace、ログ、メトリクス、成果物、承認待ち、失敗、詰まり、差分、過去履歴を材料にして、人間に理解できる状況説明へ変換する。

重要なのは、動画そのものではなく、以下である。

```text
静的な状態表示
↓
時間軸を持った状況説明
```

状況補佐官は、状況説明生成レイヤーを人間向けの役割として表現したものである。

状況補佐官は以下そのものではない。

```text
ブリーフィングタブ
テキスト要約だけ
TTSだけ
アバターだけ
動画生成だけ
計画作成AIだけ
今この瞬間だけを見るAI
```

状況補佐官は以下を説明する。

```text
過去に何が起きたか
現在どこで止まっているか
未来に何が起きそうか
なぜこうなったか
いつからおかしくなったか
どこが原因か
今は止めるべきか
進めてよいか
次に誰が何を判断すべきか
この失敗は前にもあったか
次回どう防ぐか
```

## 5. 状況補佐官の当初発想

状況補佐官の当初の発想は、以下である。

```text
自動でニュース動画を生成する仕組みが増えている。
それと同じ要領で、ワークフローやシステムの状態を自動で説明する動画を生成し、解説してもらう。
状況詳細・状況要約を、テキスト、音声、アバター、ビジュアル動画へ変換する。
現在のAIは計画を立てたり、今この瞬間の状態を見ることはできるが、状況説明なら時間軸で過去・現在・未来を説明できる。
動画ニュースのように、ナレーション・進行役として、シミュレーションゲームの解説役や進行支援アバターとして、テキスト記事として、幅広く応用できる。
```

したがって、状況補佐官は単なる「上位レイヤー」や「指示役」ではない。

正しくは、以下である。

```text
状況補佐官 = 状況説明生成レイヤーを、人間向けの役割として表現したもの
```

## 6. 状況補佐官の役割群

状況補佐官は、単一の人格や単一UIではなく、以下の役割群を統合する。

```text
コンシェルジュ: 次に見る場所を案内する
秘書: 記録・要約・差分・履歴を整理する
ナレーター: テキスト・音声・アバター・動画で説明する
報連相エージェント: 報告・連絡・相談として状態変化を上げる
状況参謀: 過去・現在・未来を整理し、リスクと次アクションを提示する
```

UI上の中心名は以下を推奨する。

```text
状況補佐官
```

設計上の機能カテゴリ名は以下とする。

```text
状況説明生成レイヤー
4D状況説明エディタ
Workflow Situation Narration Layer
```

## 7. 状況説明生成の典型フロー

ニュース動画生成は、一般に以下の構造を持つ。

```text
情報収集
→ 要約
→ 台本化
→ 音声化
→ アバター化
→ 図解・映像化
→ 動画出力
```

Agent Workflow Studio 版では以下になる。

```text
実行ログ取得
→ タイムライン整理
→ 重要イベント抽出
→ 状況要約
→ 原因候補整理
→ 未来リスク推定
→ 解説台本生成
→ 音声生成
→ アバター説明
→ ワークフロー図の動的ハイライト
→ 状況説明動画生成
→ 次アクション提示
```

## 10. 動画化・音声化すべき対象

すべてを動画化してはいけない。動画化や音声化は、認知負荷を増やす可能性がある。

動画化・音声化・アバター化すべき対象は、原則として以下である。

```text
失敗した実行
承認待ちで止まった実行
コストが急増した実行
詰まりが発生した実行
複数AIの判断が割れた実行
重要なテンプレート候補になった成功実行
人間の判断が必要な状態
長時間放置後の再開時
```

通常の細かい成功ログまで毎回動画化する必要はない。

## 12. 今後の実装判断基準

今後のIssue、PR、仕様修正では、以下を基準にする。

```text
1. その変更は、単なる表示パネル追加ではなく、人間の注意配分を改善しているか。
2. 認知HUDをBottomMonitorやHUDタブに閉じ込めていないか。
3. 状況補佐官をtext briefingだけに縮小していないか。
4. 過去・現在・未来の時間軸説明を扱える方向に進んでいるか。
5. 音声・アバター・動画を本質と混同せず、状況説明の出力チャネルとして扱っているか。
6. すべてを通知・音声化・動画化して、認知負荷を増やしていないか。
7. Scratch / n8n / Upload Labs / 認知HUD / 状況説明生成の役割を混同していないか。
8. 現在のMVPと最終構想を分けて説明しているか。
```

## 13. 受け入れ基準

この概念修正が完了したと判断する条件は以下である。

```text
- 認知HUDが「注意配分編集レイヤー」として説明されている
- 状況説明生成レイヤーが「過去・現在・未来の時間軸で説明する層」として説明されている
- 状況補佐官が「状況説明生成レイヤーを人間向けの役割として表現したもの」として説明されている
- text briefing MVPが状況補佐官全体ではなく、最小出力チャネルの1つとして説明されている
- Audio Cue / 音通知が認知HUDの表現チャネルとして扱われている
- TTS / アバター / 動画が状況補佐官の本質ではなく、出力チャネルとして扱われている
- 現在実装のHUDタブ / CognitiveHudPanel / BriefingPanel が本体ではなく暫定MVPであると説明されている
- 監査ドキュメントに、現在実装と本来仕様のギャップが明記されている
```
